# 项目侧栏状态刷新

状态：已接入，更新时间：2026-10-06。

打开 GitKit 后，项目侧栏应直接呈现未打开仓库的改动数量。原先只依赖当前仓库的工作区读取，其他项目常保留启动时的零值。本次将项目列表的只读状态读取接入现有文件监听，并区分侧栏计数与首页完整概览。

## 读取与刷新范围

- 首页或项目侧栏可见，且应用处于前台时，监控当前项目集合。首次启用、返回前台以及新的原生焦点代次均补查；不使用缓存年龄判断外部改动是否发生。
- 项目重排、名称和缓存计数变化不触发读取。新增项目只读新增路径；本地 reload 只刷新当前路径；远程检查结果按仓库行内容差分，只刷新受影响路径。
- 文件事件只刷新对应项目。健康监听没有固定周期的状态轮询。
- 首页使用 `git_project_overview`，保留上游、ahead/behind、冲突和操作等完整信息。侧栏使用 `git_project_status_summary`，只返回是否初始化、分支、去重后的改动文件数和读取时间。
- 普通已初始化仓库的轻量读取执行三次 Git 子进程：目录探测、当前分支和工作区状态。它省去完整概览的 refs、上游及操作查询，仍需执行 `git status`。普通文件夹返回未初始化；损坏或不可访问目录返回错误，不自动初始化。

## 队列与兜底

完整概览和轻量读取共用一个队列，最多同时进行三次项目读取。每个路径从实际开始读取计时，至少间隔 1000ms；事件合并为一次后续读取，持续事件不会不断推迟唤醒时间。队列默认以 32ms 小批次发布结果，其他仓库可先完成并更新计数。

监听事件订阅完成后即可开始读取，避免等待所有 OS 监听注册。注册成功后，对此前未覆盖的新路径补查一次，覆盖首次读取与监听建立之间的窗口。只有失败的监听路径启用前台 3 秒兜底；焦点恢复或项目路径变化时重试注册。当前仓库及保留的工作区监听路径由 App 的权威工作区状态负责，轻量队列跳过重复读取；这些路径的监听失败兜底调用 App 的校准入口。

1000ms 是每路径的读取限频参数，32ms 是发布批次参数，3 秒是失败监听的兜底周期，均不承诺刷新完成时限。实际延迟还包括原生事件合并、队列等待、Git 执行和界面调度。

## 前后台与结果一致性

后台暂停可选的项目状态读取和失败兜底，取消待执行定时器，丢弃迟到发布；已启动的 Git 读取允许结束，物理并发槽仍保留到完成。返回前台补查当前集合。新的原生焦点代次即使前台布尔值没有变化，也会重新配置监听并校准，覆盖 WebView 暂停期间漏收失焦事件的情况。

前台判据来自原生窗口快照：focused、visible 均为 true，且未 minimized。WKWebView 的 `visibilityState` 可能在原生窗口仍聚焦可见时为 hidden，因此 DOM 焦点和可见性事件只触发原生校准，不直接决定前后台。原生失焦事件立即置为后台，resize 重新校准最小化与恢复；不增加焦点轮询。

原生监听采用共享 owner：工作区与项目列表可共同持有同一路径的 OS watcher，一方释放不影响另一方。原生失焦释放额外的项目 owner，并检查窗口实际焦点、可见性和最小化状态；工作区仍持有的 owner 保留。配置使用单调版本，迟到的旧配置或旧释放请求不能覆盖新配置；Git 目录位置变化也只替换仍被持有的当前 watcher。

每次读取同时记录路径、请求代次和读取前的 live 状态版本。过时代次、不同路径、读取错误或比 live 更新更旧的结果不能写回项目计数；当前仓库始终保留权威 live 值。缓存可作为显示上下文，进入新读取代次时立即标记 checking。跳过 live 路径不会把旧摘要重新盖上一个新版本。有效零值可以清除改动徽标，错误保留最近已知状态。

## 资源与性能边界

监听数量随项目数量和 Git 元数据目录增加，采用 OS 文件事件；队列与缓存仅保留当前项目路径及完整概览/轻量摘要，不读取文件 Diff 或发起 fetch。后台释放项目 owner 能减少额外监听和状态读取，但不能据此声称应用完全没有后台成本。

大仓库、大量未跟踪文件、慢磁盘和文件事件密度仍会影响 `git status`、OS watcher、CPU 与内存。三并发和每路径限频约束调度频率，不等于真实资源占用保障。

一次合成的 100 个 tracking branch fixture 中，完整概览约 125ms、轻量状态约 44ms。这只是本机示例，说明省去分支概览查询的可能收益；不能外推真实大仓库、长期 CPU、RSS 或刷新 SLA。

## 验证

前端整体测试（145/145）和 Rust 测试（166 passed、4 ignored）已通过。最后的原生焦点修正及临时诊断清理后，TypeScript、生产构建和前端整体测试也已通过。前端覆盖目标规划、live 版本保护及队列生命周期回归；其中本模块与队列测试 51/51 通过。

浏览器 fixture 已验证实际 hook 的未打开仓库计数、按路径事件刷新、重排不重读、前后台恢复，以及失败监听的 3 秒兜底生效并在后台停止。live 版本与计数保护由单元测试覆盖，尚未进行对应的浏览器 fixture 模拟。

原生隔离 QA 使用三个临时仓库。在另一个仓库处于选中状态、被测仓库已退出当前及保留工作区槽时，新增文件使其侧栏计数自动从 1 更新到 2；隐藏应用后前台状态为 false，再新增文件仍保持 2，没有继续刷新。另已确认 WKWebView 可显示 hidden 而原生窗口仍聚焦可见；采用原生三状态判据后，hook 在该窗口正确为 true，并恢复计数读取。

隐藏后手动返回前台的完整原生流程未完成直接验收；恢复行为由实际 hook 的浏览器 mock 验证。上述结果不代表原生全部流程通过，也不替代真实大仓库长期运行的 CPU/RSS 测量。临时诊断和 fixture 源码已删除，隔离 QA 已退出。

本机默认 C 编译器无法解析 Command Line Tools 的新 SDK；原生 QA 使用已安装的 Xcode 编译器与 MacOSX26.5 SDK，通过进程环境指定 `CC`、`CXX`、`SDKROOT` 和目标 linker。未修改项目或系统构建配置。
